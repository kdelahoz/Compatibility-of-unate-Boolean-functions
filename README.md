# Compatibility of unate Boolean functions

This repository contains the code associated with the article:

** Compatibility of unate Boolean functions via coverage vectors **

The project implements algorithms and experiments for studying the compatibility of binary observations with unate Boolean functions. Given two sets of observations,

* `F0`: inputs observed with output `0`,
* `F1`: inputs observed with output `1`,

the main algorithm builds the corresponding discrepancy multiset and searches for a signed coverage vector

[
\Sigma \in {0,+,-}^n.
]

A coverage vector represents a candidate signed influence pattern compatible with the observations.

## Basic usage

The main function is `coverage_algorithm`, defined in `src/coverage.py`.

```python
import numpy as np
from src.coverage import coverage_algorithm

F0 = np.array([
    [0, 0, 0, 0],
    [0, 1, 0, 1],
])

F1 = np.array([
    [1, 1, 0, 0],
    [1, 0, 0, 1],
])

n = 4

D, Sigma, info = coverage_algorithm(
    F0=F0,
    F1=F1,
    n=n,
    k_max=None,
    seed=1234,
    prune=True,
)

print("Found:", info["found"])
print("Sigma:", Sigma)
print("Weight:", info["sigma_weight"])
print("Number of discrepancies:", info["d"])
```

The output `Sigma` is a signed vector in `{"0", "+", "-"}`. A nonzero entry indicates that the corresponding coordinate is selected in the coverage vector, with its inferred sign.

The function returns:

```python
D, Sigma, info
```

where:

* `D` is the discrepancy multiset generated from `F0` and `F1`;
* `Sigma` is the returned coverage vector, or `None` if no vector is found within the stopping condition;
* `info` contains metadata such as the number of discrepancies, whether a solution was found, the weight of `Sigma`, and the number of restarted attempts.

## Discrepancies

For each pair `(x, y)` with `x in F0` and `y in F1`, the code constructs a signed discrepancy vector:

* `"+"` if `x[k] < y[k]`,
* `"-"` if `x[k] > y[k]`,
* `"0"` if `x[k] = y[k]`.

The full discrepancy object is a multiset, since one discrepancy is generated for each pair in `F0 × F1`.

## Minimal subvector reduction

The algorithm includes an optional post-processing step that removes redundant coordinates from a coverage vector. This produces an inclusion-minimal coverage vector, not necessarily a minimum-weight one.

This option is controlled by the argument:

```python
prune=True
```

In the experiments, this reduction step is disabled for the computational scalability experiment and enabled for the support-recovery experiments.

## Data generation

The `Data/` folder contains the scripts used to generate the datasets for the experiments. These scripts are included so that the experimental instances can be reproduced from scratch, rather than relying only on precomputed files.

The generated datasets are then used by the scripts in the `experiments/` folder to reproduce the computational results reported in the article.

## Experiments

The repository contains scripts for reproducing the computational experiments reported in the article.

### Experiment 1: Computational scalability

This experiment evaluates the behavior of the coverage algorithm on large random instances. It measures quantities such as running time, memory usage, number of discrepancies, returned weight, and restarted attempts.

Typical execution:

```bash
PYTHONPATH=$PWD python experiments/run_exp1.py
```

### Experiment 2: Synthetic recovery

This experiment evaluates how well the algorithm recovers the true support of embedded unate Boolean functions from sampled observations.

The main reported metrics are:

* support recall,
* support precision,
* signed support recall,
* signed support precision,
* returned weight,
* false positives,
* restarted attempts.

Typical execution:

```bash
PYTHONPATH=$PWD python experiments/run_exp2_kmax10.py
```

If available, an unrestricted version can be run with:

```bash
PYTHONPATH=$PWD python experiments/run_exp2_unrestricted.py
```

### Experiment 3: Drosophila Boolean network

This experiment uses a Boolean network model associated with Drosophila. The file `src/drosophila_network.py` contains:

* the list of nodes,
* Boolean update rules,
* a parser for the rule syntax,
* functions for evaluating rules and network states,
* utilities for extracting signed supports from truth tables.

Typical execution:

```bash
PYTHONPATH=$PWD python experiments/run_exp3_drosophila.py
```

## Input validation

The file `src/io_utils.py` provides utilities for checking that the observation sets are valid binary arrays with compatible dimensions and disjoint observations.

## Reproducibility

The experiments use fixed random seeds where applicable. In the article, the base seed is:

```python
SEED = 1234
```

The `Data/` folder contains the scripts required to generate the experimental datasets, and the `experiments/` folder contains the scripts used to run the corresponding analyses. Generated result files are stored in the `Results/` directory.
